# LX Pen 音源脚本目录需求（把音源放到 /userdisk/Music 下）

> 目标读者：接手实现的人。
> 一句话：**音源脚本不要只从插件目录读** —— 要从 `/userdisk/Music` 下的固定目录读，这样换音源不用重新打包插件，插件升级也不会把用户的音源覆盖掉。

---

## 0. 状态：已实现（`plugin/qml/main.qml`）

- 用户目录固定为 **`/userdisk/Music/lx-sources/`**，启动时 `ensureUserScriptDir()` 自动 `mkdir -p`
  并放入 `example-kw-source.js` 模板；
- `scanScripts()` 扫两个目录：用户目录在前、内置 `scripts/` 在后，**同名以用户目录为准**，
  列表项带 `builtin` 标记（设置页显示「用户/内置」徽标）；
- `scriptPathFor(file)` 决定 runner 实际加载路径（用户目录优先），文件名经 `[^A-Za-z0-9_.-]` 白名单过滤防注入；
- 选中项仍以**文件名**持久化（LocalStorage `kv.script`），因此旧配置（`lx-source.js`）在文件不存在时
  自动回落到默认脚本 `lx-music-source-v6.js` 并保存；
- 每次进入设置页/插件页面都会重新 `scanScripts()`，文件增删即时可见（无需重启插件）。

实测（2026-09-20，词典笔 2AB2900000800514）：4 个内置音源在设备上均 `inited` + 酷我搜索 +
`musicUrl` 成功；默认 v6 脚本另跑了 `download` 得到 10.7MB(320k) 完整文件。

## 1. 背景与痛点

- 现在的音源脚本放在**插件目录内**：`/userdisk/PenMods/plugins/lx-pen/scripts/`
  （现有 `lx-source.js` 酷我、`sixyin.js` 六音、`example-kw-source.js` 示例）
- 协议是 **lx 音源脚本协议 v2.0.0**（`plugin/js/lx-shim.js` 提供 shim；示例见 `example-kw-source.js`：
  `globalThis.lx` → `EVENT_NAMES.request` → action `musicUrl`）
- 问题有两个：
  1. **音源会过期**：各平台接口 URL/签名参数随时变（`lx-music-port/README.md:85` 自己写了这条风险），必须能随时换脚本；
  2. **插件目录会被升级覆盖**：重新打包/覆盖插件时，用户自己的音源脚本会被一起冲掉 ✗。

## 2. 需求

把音源脚本目录改为**可配置 + 默认落在 `/userdisk/Music` 下的固定目录**：

| 项 | 要求 |
| --- | --- |
| 默认目录 | `/userdisk/Music/lx-sources/`（名字可再定，但要求纯 ASCII、路径短、和 `/userdisk/Music/Rime` 同级风格一致） |
| 内置目录 | 插件自带的 `scripts/` 仍保留，作为**兜底/模板**（找不到用户目录时可用） |
| 扫描时机 | 插件启动、进入设置页、以及每次"音源"下拉展开时重新扫描（文件增删即时可见） |
| 列表面板 | 设置页的音源选择列出：**文件名 + 所在目录**（区分内置/用户），并标出当前选中项 |
| 持久化 | 选中的脚本路径写入插件配置（重启保持）；路径失效时回落内置脚本并提示 |
| 目录初始化 | 用户目录不存在时自动创建，并放一份 `example-kw-source.js` 作为模板（用户复制改名即可） |
| 错误提示 | 三类错误要分开提示：脚本不存在 / 语法错误（加载失败）/ 接口报错（搜不到歌）；不要静默失败 |
| 明确不做 | **不做 U 盘导入**（用户已明确要求）；不做网络下载音源 |

## 3. 为什么放 /userdisk/Music 下

1. **持久**：`/userdisk` 是可写的 6.5GB 分区，插件升级覆盖 `plugins/` 时不受影响；
2. **可管理**：PenMods 的文件管理器根目录就是 `/userdisk/Music`，用户能直接用笔上的文件管理器查看/替换音源；
3. **同一套约定**：Rime 数据已经是这个模式（`/userdisk/Music/Rime`），保持一致；
4. 换音源**不需要重新打包插件、不需要重新部署**。

## 4. 实现要点（供参考，具体以插件现状为准）

1. 读脚本的地方（runner / `runtime.js handleScript` 一侧）把"脚本路径"从**写死插件目录**改成**从配置读 + 默认用户目录**；
2. 扫描函数返回 `[{name, path, builtin:bool}]`，交给设置页列表；
3. 选中项存配置（插件现在已有 `/tmp/lxpen_state.json` 这类临时状态，注意**选中项要落到持久配置**，不能只放 `/tmp`）；
4. 加载失败时保留上一次可用的脚本（或回落到内置），避免"选了个坏脚本就完全不能用"。

## 5. 验收标准

1. 往 `/userdisk/Music/lx-sources/` 放一个新 `.js` → **不重启插件**，设置页音源列表里能立刻看到并选中；
2. 选中后能正常搜索/播放/下载（用现有酷我/六音脚本验证）；
3. 把该文件删掉 → 列表里消失；若它是当前选中项，给出明确提示并回落到内置脚本；
4. 覆盖/重新部署插件（覆盖 `/userdisk/PenMods/plugins/lx-pen/`）后，用户目录里的音源脚本**仍在**、选中项**仍在**；
5. 放一个语法错误的脚本 → 提示"加载失败"而不是静默搜不到歌；
6. 全程不涉及 U 盘路径。

## 6. 附带建议（可选，非必须）

- 设置页显示当前脚本的 `@version` / `@name`（脚本头部注释里通常有，`example-kw-source.js` 就是这种格式），方便判断音源新旧；
- 音源请求失败时在日志里记录平台 + 接口名，便于快速判断"是音源过期还是网络问题"。
